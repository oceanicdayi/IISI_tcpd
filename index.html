TCPD Fast 運作說明

go-tcpd-fast 接收測站的 P 波 pick，在記憶體內完成觸發判定、定位與規模估算，再把速報以 Earthworm Link 格式送給下游。本頁依 TCPD_Source 原始碼整理，用來對照需求，也作為後續開發的依據。

概觀

一個地震事件從 pick 進來到速報送出，會經過下列五個階段。各階段的細節在後面的章節。

  1. 接收 pick上游以 TCP 連入 :16001，每筆是 14 個欄位的文字。
  2. 觸發判定篩選後的觸發站要有 4 站以上，才會進入計算。
  3. 定位與規模第 1–3 報用形心法，第 4 報起用 Geiger 疊代加深度網格；規模取 Mpd，並參考 Mtc。
  4. 發報觸發站數每增加一次就重算再發，最多 11 份；前 3 份要通過 10 秒與 PGA 閘門。
  5. 結束首報後 60 秒，或站數連續減少，就清空狀態等下一個地震。

輸入

  • P 波 pick：TCP :16001，Type 150，每筆 14 個文字欄位
  • 上游心跳：Type 3
  • YAML 設定檔：預設 tcpd_fast.yaml

輸出

  • EEW 速報：TCP 連往下游，Type 150，19 個文字欄位
  • 心跳：每 15 秒一次
  • .rep 詳細報告檔，依事件分資料夾
  • 三份日誌，以及 :8080 的 Prometheus 指標
名詞

pick：測站偵測到 P 波後送出的一筆資料。觸發站：通過篩選、參與本次計算的測站。報告：一份 EEW 速報。事件：同一個地震的連續報告，共用同一個事件編號（numEew）。

程式架構

整個服務是一個行程。pick 從左邊進來，經過一條有容量的佇列交給單一的計算引擎，引擎產生的報告交給送出端；日誌與指標由所有元件共用。

啟動與關機順序

  1. 解析命令列：-c 設定檔，或第一個位置參數；預設 tcpd_fast.yaml。
  2. 載入 YAML，建立 service、network、event 三個 logger。
  3. 啟動 Prometheus HTTP 伺服器。
  4. 註冊 SIGINT / SIGTERM。
  5. 建立容量 256 的 pickCh，啟動送出端，再為每個 pick 監聽位址啟動一個接收器；任何一個接收器啟動失敗就直接結束程式。
  6. 啟動定時心跳。
  7. 執行引擎主迴圈，直到 Context 被取消；收到結束訊號後各元件依 Context 收尾。
設計取捨

不回送心跳給上游。上游的 export_gen_actv 自己會依 SendAliveInt 送心跳。本端若回送，會被它判定為 "weird heartbeat from client" 而自行終止重啟，pick 就送不進來。這個現象在實測中確認過，所以 main 沒有呼叫 WithHeartbeat。

下游斷線時報告不暫存。連線不存在時 Send 直接回傳 "not connected"，引擎只記一筆警告，之後不會補送。

Pick 資料界接

tcpd-fast 是 TCP 伺服器，上游（export_ew 等）主動連進來。可以同時監聽多個位址：pick-listen-addr 與 pick-listen-addrs 會合併去重，每個位址各有一個接收器。這是為了讓不同測站網路各自送到不同的埠。

同一測站會在 P 波後陸續送來多筆（upd_sec 不同，P_epoch 相同），每筆只帶一個 Pd。引擎之後會把它們合併。Pa、Pv、Pd 的單位由上游決定，程式不做換算。

連線健康與逾時

  • 每條連線各自記錄最後活躍時間，只有 pick 或 Type 3 會更新它。
  • 超過 upstream-timeout（預設 30 秒）沒有任何 pick 或心跳，就關閉這條連線，並把 tcpd_pickreceiver_upstream_healthy 設為 0。
  • 上游關閉連線時，這條連線的 goroutine 結束，eew_pick_receiver_connections_active 減 1。

狀況結果

演算邏輯

引擎在一個迴圈裡等兩件事：pickCh 來了新 pick，或 100 ms 的計時器響了。每收到一筆 pick 就跑一次完整的處理週期；計時器則只負責檢查事件是否該結束。

處理一筆 pick

  1. 取出一筆 pick從 pickCh 取得，開始計時（寫入 eew_engine_process_duration_seconds）。
  2. 判斷分量第 3 碼是 Z 嗎？
    否 → 丟棄
  3. 判斷權重夠好嗎？一般測站要 Weight < ignore-weight-p；YOJ、EOS2、EOS3、EOS4 固定要 Weight < 3。
    否 → 丟棄
  4. 存入緩衝區放進第一個空槽（共 1000 槽），Flag = 1。槽全滿時這筆會被靜默丟棄。
  5. 清除過期並合併重複移除 |現在 − P 到時| > active-parr-win 的 pick。同站、同 P 時間的多筆更新合併成一筆，保留 UpdSec 較大者，並補入較小者的 Pd。
  6. 算形心，選出觸發站形心是所有有效 pick 的平均經緯度與平均 P 時間。與形心距離不超過 trig-dis-win、與平均 P 時間差不超過 trig-tm-win 的測站入選；13 個保留前綴不受這兩個限制。
  7. 判斷觸發站數 ≥ 4？
    否 → 等待，countMax 歸零
  8. 判斷countMax > report-limit？countMax 是觸發站數連續低於歷史最大值的次數。
    是 → 當作新地震，重置事件並結束本次處理
  9. 判斷觸發站數 > 歷史最大值 maxSta？成立時先把 maxSta 更新為目前站數。
    否 → 略過。相等：不處理；較少：countMax + 1
  10. 判斷已發報告數 repFin ≤ 10？
    否 → 略過，這個事件已發出 11 份
  11. 定位repFin < 3 用 Locaeq（形心法）；否則用 LocaeqOri（Geiger 疊代加深度網格）。兩者都會依品質反覆剔除離群站再重算。
    剔除後站數不足（快速 < 4、標準 < 5）→ 放棄
  12. 判斷非共站站數夠嗎？快速模式 ≥ 4、標準模式 ≥ 5，而且要比上一份報告的站數多。
    否 → 放棄
  13. 估算規模Magnitude() 回傳 XMpd、Mtc、Padj。
  14. 判斷mag-min ≤ XMpd ≤ mag-max？
    否 → 不發報，event 日誌記 Warn
  15. 組成速報repFin + 1，組出 19 個欄位的字串，算出處理時間 proTime。
  16. 判斷通過早期發報閘門？只有第 1–3 份需要：proTime < 10 s；若 pv-thr 與 intensity-thr 都是 1，還要 PGA 場址數 > 0 且 Q > 0。
    否 → 不送下游，但仍寫 .rep
  17. 送往下游，寫 .rep字串交給送出端；eew-output-dir 不是空字串時寫一份 .rep。
注意

第 9 步先更新了 maxSta，後面任何一步放棄時它都已經改掉。所以同一個站數的計算沒通過，就不會再試，要等到觸發站數再增加才會重算。

計時器那一側

每 100 ms 檢查一次：已經發過報告，而且距離第一份報告超過 60 秒，就重置事件。這是事件正常結束的主要方式，詳見事件結束條件。

觸發條件與門檻

要發出一個事件的第一份報告，需要同時滿足下面幾件事。前三項決定「有沒有地震」，後面幾項決定「算出來的結果夠不夠格發出去」。

  1. 測站要先成為觸發站。pick 要是 Z 分量、權重過關、還在存活時間內，而且落在形心的距離與時間視窗裡（保留站除外）。
  2. 觸發站至少 4 站。3 站以下只會等待。
  3. 觸發站數要創新高。只有比歷史最大值多才會重新計算。
  4. 共站只算一站。互相距離小於 0.5 km 的測站視為同一站，成對時只保留陣列中排在後面的那一筆，排在前面的標為無效。
  5. 非共站站數要夠，且比上一份報告多。
  6. 規模要落在 mag-min～mag-max。判斷的是 XMpd。
  7. 前 3 份要通過早期閘門。

地震定位

定位有兩套方法。前三份報告用形心法，追求速度；第四份起用 Geiger 疊代加深度網格，追求準確。兩者共用同一個距離函數與速度模型。

距離計算：Delaz

用兩點的平均緯度，以三次多項式算出每分角對應的公里數，再把經緯度差換算成平面距離。

φ̄ = (φ₁ + φ₂) / 2 a = 1.840708 + φ̄·(0.0015269 + φ̄·(−0.00034 + φ̄·1.02337×10⁻⁶)) b = 1.843404 + φ̄·(−6.93799×10⁻⁵ + φ̄·(8.79993×10⁻⁶ + φ̄·(−6.47527×10⁻⁸))) 距離 = √( (a·Δλ·60)² + (b·Δφ·60)² ) 單位 km

在北緯 24° 附近，1 度緯度約 110.76 km，1 度經度約 101.74 km。形心距離、共站判定、剔除最遠站、規模的震源距、PGA 預估都用這個函數。

速度模型與走時

程式依震源深度 z 選一組參數：z 小於分界深度用淺層，否則用深層。選定後速度隨深度線性增加，v(z) = v₀ + vg·z。Z 分量用 P 模型，水平分量用 S 模型；目前只有 Z 分量的 pick 會進來，所以定位實際只用 P 模型，S 模型只用來算 S−P 時間。

zc = −v₀ / vg xc = (Δ² − 2·(v₀/vg)·z₀ − z₀²) / (2Δ) ang₁ = π − atan((z₀ − zc) / xc) （atan 為負時先加 π） ang₂ = atan(−zc / (Δ − xc)) 走時 t = −(1/vg) · ln | tan(ang₂/2) / tan(ang₁/2) |

Δ 是震央距，z₀ 是震源深度。入射角 ang₁ 也用在 Geiger 疊代的偏導數。

快速定位：Locaeq（報告 #1–#3）

  1. 只取 Z 分量的測站做平均。
  2. 震央取這些測站經緯度的平均；發震時間取平均 P 到時再減 2.0 秒；深度固定 10 km。
  3. 方位角空隙 Gap：把各站相對震央的方位角排序，取相鄰兩站的最大間隔（首尾接成一圈）。
  4. 算各站到震央的距離，得 MaxDis 與 AvgDis；Q 是 Pv > 0.257 且位置碼為 01 的 Z 測站數。
  5. 每站的 Perr 設為 0、Wei 設為 1，Averr 與 Avwei 都是 0。

這個方法不用速度模型，也不做殘差檢查。引擎在它外面包了一圈：MaxDis 大於等於 max-epi-dis 時，剔除最遠的測站再重算，剩不到 4 站就放棄。因此前三份報告的 Averr 與 Avwei 都是 0。

標準定位：LocaeqOri（報告 #4 起）

  1. 初值。深度 10 km；取 P 到時比平均早 0.5 秒以上的 Z 測站，震央取它們的座標平均，發震時間取它們的 P 平均減 2.0 秒。沒有這種測站時，以第一站附近當起點。
  2. 線性化尺度。在初始震央上用 Delaz 算一次每度緯度、每度經度的公里數，整個疊代過程不再更新。
  3. Geiger 疊代，共 10 次。每次做下面四件事：
    1. 對每個測站算震央距、理論走時與入射角，以及走時對經度、緯度、深度、發震時間的偏導數；殘差 Perr = P − t0 − 走時；權重用 Wt。
    2. 先用加權平均殘差修正發震時間。
    3. 建立加權正規方程，各項除以平均權重，對角線加 10⁻⁵ 的阻尼，反轉 4×4 矩陣，解出四個修正量。
    4. 更新經度、緯度、深度、發震時間。若發震時間偏離初值超過 60 秒，整組參數退回初值，避免發散。
  4. 深度網格搜尋。固定震央與發震時間，把深度依序設為 10、20、…、100 km（程式用 (k)×10.0001），每個深度計算 Σ Wei·|Perr|，取最小者為最終深度。
  5. 定稿。以最終深度重算各站 Perr、Wei，並用 S 模型與 P 模型相減得到 S−P 時間；Averr 是殘差的均方根，Avwei 是權重的均方根；再算 Q 與 Gap。

疊代階段的深度可以自由變動，但最終深度由網格覆蓋，所以疊代主要決定震央與發震時間，網格才決定深度。引擎外層另外檢查：Averr 要在 0.1–0.8 秒之間，且 Avwei ≥ 0.3，不然就剔除殘差絕對值最大的測站再算，剩不到 5 站就放棄。

規模計算

每個測站各自用位移振幅 Pd 與特徵週期 Tc 算出一個規模，再把全部測站做加權平均。對外發報與範圍檢查用的是 XMpd（Pd 為基礎的規模），Mtc 只放在 .rep 與綜合規模裡。

計算步驟

  1. 標記排除的測站。在 mag-reject 名單（站名、分量、網路、位置碼四項完全相符）、位置碼為 02、非 Z 分量、Tc < 0、UpdSec < 2 者，Flag 設為 2，不參與。
  2. 逐站算規模。Pd 取 Pd[min(UpdSec, 2)]；震源距 R = √(depth² + Δ² + 10⁻⁶)；依儀器類型用對應公式算 Mpd；Tc > 0 時另算 Mtc。算出來大於 0 的才收進清單。
  3. 站數檢查。有效 Mpd 不到 4 筆，規模直接視為 0；因為 0 小於 mag-min，引擎會記一筆「out of bounds」警告而不發報。
  4. 離群過濾與加權平均。先求平均與標準差（母體標準差），保留 z < 1.0 者，以測站權重 Wei 加權平均，得 XMpd；Mtc 同樣處理。
  5. 綜合規模 ALLMag。Mtc 與 XMpd 都大於 0.001 時取兩者平均，否則取 XMpd。若 XMpd 小於 0.01，ALLMag 與 XMpd 都歸零。

countMax 如何累積

每次處理週期，觸發站數比歷史最大值少，countMax 加 1；比歷史最大值多，歸零；相等，不動。以 report-limit = 1 為例，連續兩個週期站數偏少時 countMax 變成 2，第三個週期開始時判斷 2 > 1 成立，就重置。這代表原本集中的 pick 已經散開，通常是第一個地震結束、下一個地震開始。

重置會清掉什麼

  • 緩衝區所有 pick（Flag 全部設為 0）。
  • countMax、maxSta、repFin 歸零；上一份報告的比較基準回到初始值。
  • 事件編號 numEew 加 1，超過 10000 回到 1。

firstRpTime 與事件資料夾名稱不會清除，會在下個事件的第一份報告時覆寫。

待確認

重置時緩衝區是整批清空，不分哪個 pick 屬於哪個地震。若第二個地震的 pick 在重置前已經進來，也會一起被清掉。

日誌檔

日誌分成三份，各有各的內容與切檔。三份共用 log-level，路徑在 log-path（預設 logs）底下，依模組分子資料夾。

檔案內容寫入者
service/tcpd_service.log服務生命週期：載入設定、參數回顯、啟動與關機、metrics 伺服器。main、metrics
network/tcpd_network.log連線層：上游連入與斷開、逾時、對下游的連線、重連、心跳。eewsender、pickreceiver
event/tcpd_event.log事件計算：pick 解包、過濾、觸發、定位、規模、發報、.rep 輸出、事件重置。eewengine、pickreceiver

行格式

時間（本機時區，毫秒）  [等級]  (模組::動作) 訊息內容
2026-10-13 14:02:11.486 [info] (Engine::Publish) EEW Report #4 successfully forwarded to DCSN upstream
  • 時間格式是 2006-01-02 15:04:05.000。容器映像把時區設成 Asia/Taipei，所以日誌是台灣時間，而 .rep 與速報裡的時間是 UTC，兩者要換算。
  • 等級字串是 logrus 的名稱：debug、info、warning、error、fatal。注意警告是 warning，不是 warn；log-level 設定可以寫 warn。
  • 程式沒有使用 logrus 的結構化欄位，行尾不會有 key=value，數值都在訊息文字裡。

切檔與保留

  • 單檔 10 MB 就切檔，最多保留 30 份，超過 90 天的刪除，用本機時間命名。
  • 每天本機時間 00:00 另外強制切一次，所以每天的日誌分開存放。舊檔會被改名成像 tcpd_service-2026-07-15T00-00-00.000.log 的帶時間戳檔名。
  • log-console 為 true 時同時輸出到標準輸出。三份日誌都會輸出，主控台上會混在一起。
